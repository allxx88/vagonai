# История посетителя и постоянный профиль

Внедрено 7 октября 2026 года. При загрузке страницы и нажатии часов сайт
запрашивает последние 10 сообщений (пользователь и агент вместе) из PostgreSQL.
Сообщения группируются по диалогам; нажатие открывает сохранённый диалог.
Имя используется в приветствии. Имя, компания, телефон и email хранятся
в отдельной таблице `visitor_profiles` и передаются агенту даже в новом диалоге.

## Как определяется посетитель

`vagonai_memory_visitor_id` в localStorage — случайный секретный UUID браузера.
Он передаётся только своему n8n по HTTPS. История фильтруется на сервере
по этому ключу, а профиль хранится под его SHA-256. Нельзя читать переписку
по одному ID диалога. Ключ нельзя публиковать или передавать другому человеку.
Без регистрации восстановление работает в том же браузере. Очистка данных
сайта, другой браузер или другое устройство потребуют отдельного входа в аккаунт.
LocalStorage содержит только резервную копию истории для сетевых сбоев.
Кнопка очистки очищает эту локальную копию; записи в PostgreSQL сохраняются.

## Компоненты

- n8n `8fbv0vLrGbslOMwX`: основной POST `/webhook/chat_vagon`.
- n8n `VagonVisitorHistory2026`: POST `/webhook/chat_vagon_history`.
- `vagonai-chat-history`: Python + psycopg, порт 8080 только внутри Docker-сети.
- PostgreSQL `chat_memory`: `provagon_chat_memory` и `visitor_profiles`.
- Контакты извлекаются из явно сообщённых сведений. Дополнительный агент
  Extract Visitor Profile использует существующее подключение Gemini.
  Он не заменяет коммерческий анализ заявки.

Новый ngrok адрес автоматически обновляется в `api/endpoint.json`.
Endpoint истории строится на том же адресе; ручная смена не нужна.

## Восстановление сервиса

Из корня репозитория:

```bash
docker --context desktop-linux compose \
  --env-file /home/allxx/n8n/postgres/.env \
  -f services/chat-history/compose.yml up -d --build
```

Сервис получает только `APP_PASSWORD`. PostgreSQL и n8n должны находиться
в сети `n8n_n8n-network`. Порт базы и порт сервиса наружу не публикуются.

Для добавления узлов к резервному экспорту исходного workflow:

```bash
python3 services/chat-history/prepare_workflows.py backup-workflow.json --output /tmp/vagonai-workflows
```

Генератор рассчитан на исходный workflow с узлами Validate Input,
Агент Продавец, Агент анализ заявки и Google Gemini Chat Model1.
Не запускайте повторно поверх уже расширенного workflow.
Импортируйте оба созданных JSON в тот же проект n8n, проверьте credentials
и опубликуйте. При публикации через CLI перезапустите n8n.

## Проверка

Сообщите тестовое имя и компанию, email `test@example.com` и вымышленный
телефон. Обновите страницу: имя должно появиться в приветствии.
Нажмите часы, откройте диалог. В новом диалоге спросите, какие контакты
сохранены. В другом браузере данные первого посетителя не должны появиться.

Автоматическая интеграционная проверка использует собственный случайный
тестовый ключ и удаляет только созданные ею тестовые записи:

```bash
docker --context desktop-linux exec -i -e PYTHONPATH=/app \
  vagonai-chat-history python - < services/chat-history/test_history.py
```

Проверяются ровно 10 последних сообщений, порядок, постоянный профиль,
изоляция посетителей и запрет чужого ID диалога.
